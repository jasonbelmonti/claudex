# @jasonbelmonti/claudex 3.0.0 Release Notes

Version 3.0.0 is the next semver-major release over the published 2.1.1 line.
It prepares the package for first-class Copilot provider support and makes the
Node-only runtime contract explicit in package metadata.

## Breaking Changes

- Node 20 or newer is now required. The published package metadata changes from
  `engines.node >=18` to `engines.node >=20`.
- Bun is not part of the supported runtime, repository validation, or release
  contract. Existing Bun-based setups should move install, CI, package checks,
  and smoke tests to standard Node and npm workflows.
- `ProviderId` now includes `"copilot"`. Consumers with exhaustive provider
  switches should add a `copilot` branch or a capability-first fallback.

## Added

- GitHub Copilot SDK runtime support as an opt-in beta/provider-preview path.
- `copilot` provider registration through `ClaudexAdapter` when explicitly
  included in `preferredProviders` or injected via provider configuration.
- Copilot readiness reporting, session creation/resume, buffered and streamed
  turns, structured output validation, token usage normalization, file-change
  events, approval request/resolution events, MCP session descriptor mapping,
  and deterministic contract coverage.
- Copilot live smoke test entrypoint gated by local Copilot auth and
  entitlement.

## Unchanged Boundaries

- Copilot is not part of the default provider resolution order. The default
  remains Codex first, then Claude.
- Passive ingest still replays local Claude and Codex artifacts only. Copilot
  live SDK support does not imply Copilot passive-ingest support.
- Provider-specific advanced surfaces such as hooks, plugins, managed MCP
  servers, fork semantics, image attachments, and cost telemetry remain
  capability-gated or provider-specific.

## Validation Before Tagging

Run the deterministic release gates on the release-prep branch before creating
the `v3.0.0` tag:

```bash
npm run check
npm test
npm run test:coverage
npm run package:check
```

The release workflow also validates that a tag push named `v3.0.0` matches the
package version before publishing to npm. A manual `workflow_dispatch` run is a
rehearsal only and does not publish.

Authenticated smoke tests are optional release evidence because they depend on
local provider availability:

```bash
npm run test:smoke
```
